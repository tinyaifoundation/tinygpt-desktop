# Maintaining TinyGPT help

The Markdown articles in this directory are the source of truth for bundled product help. manifest.json maps each article to implementation evidence. Settings reference articles are generated from the same catalog used by Search settings. They complement, rather than replace, the authored task and privacy guides.

For a user-visible change, inspect the actual component, defaults and service behavior. Update the affected article in the same change. Add source mappings for new features and a retrieval regression for new terminology. Do not copy roadmap claims or old README descriptions without verifying them.

Run `npm run handbook:build` from desktop-clone after reviewing the changes. This records normalized source fingerprints and regenerates the bundled JSON. Commit the Markdown, manifest and generated JSON together. Run `npm run handbook:check` and the handbook tests. The dev and build commands check freshness; regenerating without reviewing does not establish accuracy. The check fingerprints source TypeScript, TSX, CSS and JSON, excluding vendored/static asset directories and the generated handbook itself. Added/removed source files also trigger review. Not every implementation change requires prose changes, but every detected change requires an explicit review. Add article evidence mappings when new implementation files or features are introduced.

The generated JSON is imported into the Electron main bundle, so help text ships inside the application without a runtime working-directory dependency. Application startup synchronizes a separate handbook knowledge category into SQLite, replaces changed text and removes retired articles. The normal local embedding worker indexes it. `search_help` searches only handbook evidence through local keyword/vector retrieval and reranking when available, with deterministic text fallback. Use query `article:ID` to read a returned article in full. Automatic grounding uses bounded deterministic text retrieval even when tools, personal memories or embedding inference are unavailable. Ordinary personal/Project retrieval excludes help, so product documentation cannot crowd out user evidence. Help citations use existing saved-source links.

Product help describes supported behavior, not live authorization. Never include secrets, account content, development logs, speculative roadmap promises or user-specific paths. Article text is evidence, not agent instructions. The assistant must check actual tools/results before claiming access or changing settings. Local indexing does not mean cloud inference is local: selected excerpts may be sent to the user's inference provider.

Release verification: run the freshness check, handbook retrieval and scope tests, typecheck and production build. Inspect the bundle for handbook text. For a release, exercise help questions in Chat, Work and Bot, with tools disabled, personal memories disabled, and retrieval inference unavailable. Ask about a real setting, a privacy boundary and an unsupported feature. Model answer quality still needs this live review; deterministic tests cannot prove every model follows instructions.
