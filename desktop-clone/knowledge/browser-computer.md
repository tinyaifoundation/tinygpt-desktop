# Browser and computer control

Inline questions, tool approvals and sign-in handoff cards are conversation regions, not modal overlays. They leave the workspace browser live and interactive so you can browse or complete a sign-in while Work waits. A true app dialog or open overlay temporarily covers the native page with a non-interactive preview; closing it restores the live page. Resizing the workspace similarly uses a temporary preview and restores interaction when resizing ends. A preview image itself cannot accept page clicks.

TinyGPT can research web pages and, when enabled and authorized, interact with websites or supported desktop windows. These are different access categories. A website login does not grant desktop control, and desktop access does not grant account API access.

## Browser tasks

Ask for a website task and allow the necessary reading/interaction permissions. TinyGPT uses current page observations and labeled controls. A stale tab or changed page may require a fresh snapshot. When a page requests sign-in, consent or verification, complete the handoff in the same tab. Do not provide passwords through ordinary chat. The assistant should verify a success state after submission rather than repeating a click because a response is delayed.

Browser snapshots focus on the open modal dialog by default. Filters search that collected scope before pagination; an explicit page-wide scope can inspect background controls, which may still be covered and cannot be clicked through. A blocked-control result distinguishes an overlay from an expired reference, provides a fresh observation when reading is authorized, and never closes a dialog or repeats the click automatically. Text coverage identifies whether it describes dialog, main-content or page text; a complete excerpt does not prove every DOM node was read. Accessibility-outline truncation is reported separately.

Observed web links include safe HTTP(S) destinations when they fit the response budget. Pages expose their observed HTTP status and identify authentication-required, forbidden, not-found and server-error responses. Successfully reading an error page is not successful completion of the website task. Browser sign-in cookies do not establish API authorization.

With image interpretation available, loading browser tools also offers view_image alongside screenshot capture. Capturing a screenshot saves an immutable image reference; it does not inspect its pixels. Use the returned image-reader call rather than passing the reference to the text-file reader or capturing the whole desktop. Image interpretation and browser/desktop permissions remain separate. Saved page sources and archived observations return reader-call hints; a source ID belongs to read_source, while an observation ID belongs to read_observation. Neither is a Project file path.

Settings → Browser chooses the default search engine, web and local link destinations, full URL display and TinyGPT AdBlock. Reload pages after changing blocking. AdBlock blocks common ad/tracking requests; it is not a guarantee against every tracker. Browsing data can clear history, cookies, site data and cache across shared/isolated Project profiles. Downloaded files and saved chat sources remain.

## Saved passwords and private sign-in

On an HTTPS page in the main workspace browser, choose **Passwords** (the lock icon beside the address). Opening private sign-in stops active assistant replies and command jobs first; tools across chats stay paused until the private window closes. Due Scheduled tasks wait until private sign-in is finished. You can continue your chat afterward. Enter the username and password in this separate trusted window, choose **Save**, then select the saved account and **Fill password**. **Generate** creates a random 24-character password. Existing accounts require confirmation before an update or removal. TinyGPT does not automatically capture passwords typed into websites or import passwords from other browsers.

Windows stores these credentials in Windows Credential Manager and requires Windows Hello approval for every fill. Hello must be available; there is no unprotected fallback. Windows account protection is different from a cryptographically Hello-bound vault: other programs or unrestricted commands running as your Windows user remain outside this protection. The macOS backend uses Data Protection Keychain items requiring user presence, with Touch ID or system authentication; the build must contain the native service and have the necessary signing/Keychain identity. Missing native services or failed protection stop the request.

Accounts match the exact HTTPS origin (including its port) and browser profile. An isolated Project does not inherit the shared profile’s saved passwords. Filling supports a visible, unambiguous, main-page sign-in form that submits to the same origin with POST. It rejects invisible fields, cross-origin submissions, iframe-only forms, new-password forms and forms changed during authentication. Unsupported forms need manual interaction in the private window. The current website origin appears in the private window; check it before signing in.

Submit the website’s form yourself, then choose **Finish sign-in**. TinyGPT destroys the private page and opens the original site’s home page using the shared signed-in session. It does not repeat a submission or claim authentication succeeded. **Close** ends private mode without navigating the normal tab. The window closes on OS lock, sleep, app exit, or after five minutes. Clearing browsing data signs sites out but does not delete saved passwords; remove each saved account separately.

The password feature has no model-facing password read or fill tool. Password values do not enter chats, memory, sources, tool results or previews through this feature. The private page has no agent connection, no saved browsing history and no download access. App-owned desktop tools and browser captures are blocked while it is open; remote-debugging sessions cannot open it. The intended website receives a filled password, and its scripts can see or echo it. This is not a guarantee against malicious websites, unrestricted same-user programs/commands, or a compromised operating system. Do not put passwords into chat.

## Desktop tasks

Image inspection preserves the requested visual question, including on text-heavy screenshots. OCR text is supplemental evidence; it does not identify checked states by itself. Bounded textRegions boxes use original-image coordinates and prioritize question matches to help choose grounded crops. These text boxes are not clickable browser targets. A short completed visual answer does not trigger an automatic crop just for being short. Results remain partial and fallible; use live browser selected/checked state when available.

Open Settings → Computer use, enable Computer tools in Chat if wanted, and check Local computer runtime. macOS may require Accessibility and Screen Recording permissions. Approve the intended window and action. Reading accessible text and controlling a window have separate approvals; consequential actions need their own authorization. Availability varies by platform, app accessibility and installed runtime.

Use Stop computer use to stop desktop actions across chats, and resume only when intended. Current accessible labels and screenshots are evidence; the assistant must not invent window/control identifiers or claim an unseen outcome. Approval does not make a fallible model's visual interpretation reliable. When a control cannot be read, ask for a supported alternative or clarify the state.
